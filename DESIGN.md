# MailSchema visual system

## Reference and setting

Selected Direction 03, the yellow-and-blue board. A developer opens the project on a desktop in a bright workday, first exploring its identity, then settling into sustained specification reading. Dark, high-contrast brand sections establish the identity; a mist-light reader supports sustained reference work.

## Color strategy

Full palette with explicit roles: charcoal foundation, acid yellow-green for the next action, blue-violet for structured information, cool mist for reading. All implementation tokens use OKLCH. No gradient text, decorative glass or accent side borders.

The specification reader has light and dark modes. Dark reading uses a charcoal surface, light text, brighter violet links and restrained violet navigation highlights. The masthead and acid yellow-green status accent retain their colours in both modes. Sourcey owns the toggle and saved preference; MailSchema supplies its brand accents.

## Typography

Preserve the selected board's Plus Jakarta Sans identity, self-hosted. Heavy tightly tracked wordmark and display type, comfortable medium-weight body text, ordinary sentence case. Monospace is limited to examples and identifiers. Body measure about 68ch.

## Layout

Wide dark homepage with a luminous structural mark, oversized but concise heading and clear draft status. A strong MAP specification band, a real interactive email review, and differentiated Types/Registry destinations. Reader uses a persistent navigation rail, generous article column and quiet on-page contents. Mobile retains every route and readable examples.

## Components and motion

Crisp near-square surfaces, capsule primary controls, fine full borders and subtle iconography. Small directional hover transitions; no bounce or scroll hijacking. Respect reduced motion. Code copy gives inline feedback. Search filters local documentation; no external runtime services.

## Status language

Working draft, proposed type, planned implementation. The local demonstration simulates authorization and results; it does not perform account actions. Core stays in MAP until separately useful.
